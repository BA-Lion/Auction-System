# fund_outbox — 资金任务表

整理日期：2026-11-17。依据 [confirm-design v1.1](../confirm-design/README.md)；共同约定与待定边界见 [目录说明](./README.md)。

## 字段

| 字段 | 含义及已确定约束 |
| --- | --- |
| id | 任务主键，对应 Kafka 消息 outbox_id |
| round_id | 所属场次 ID |
| user_id | 任务所属报名用户，超时任务为买家 |
| event_type | 未中拍押金解冻／订单超时处理 |
| biz_id | 报名记录 ID 或订单 ID，取决于任务类型 |
| 关联流水编号（承载待定） | 预生成并持久化的各资金效果雪花号 |
| payload | 业务载荷，具体结构待定 |
| status | 待完成／SUCCESS／待投死信／已投死信等语义 |
| retry_count | 持久化补发次数，首发为 0 |
| last_attempt_at | 最近发送尝试时间 |
| last_error | 最近错误信息 |
| completed_at | 业务完成时间 |
| created_at | 创建时间 |
| updated_at | 修改时间 |

## 约束与业务使用

约束：主键 id；UNIQUE(round_id, user_id)。当前同一报名的未中拍解冻与第一名超时任务互斥，所以采用该唯一键；不扩展为所有未来事件的通用唯一键。已讨论扫描索引方向：(status, last_attempt_at)。

消费者用 outbox_id 定位本表，再核对 event_type、biz_id 与业务数据。不能混用任务 ID、业务 ID 和流水 ID。找不到任务或身份冲突不能继续执行资金动作。

SUCCESS 表示业务数据库事务完成，不表示 Kafka 投递成功。解冻、超时补偿、零尾款兜底将资金效果与任务 SUCCESS 同事务提交；正常主动付款无对应任务时不强行创建任务。

距最近尝试超过 10 分钟、未成功且 retry_count < 5 时，重发前先原子领取、增加计数和记录尝试时间。第 5 次仍有发送机会，再经过一个 10 分钟窗口未成功进入死信流程；死信 ACK 后记录投递完成，迟到业务成功优先。

### 待细化的字段

一个结算任务产生多条流水，原单 flow_id 不足以表达；编号集合是否写入 payload、是否保留独立列、零尾款兜底编号如何绑定尚未确认。每条流水独立编号和业务幂等是确定要求。领取租约字段、完整状态枚举、字段类型与载荷格式仍待实现设计。
