# fund_flows — 资金流水表

整理日期：2026-11-17。依据 [confirm-design v1.1](../confirm-design/README.md)；共同约定与待定边界见 [目录说明](./README.md)。

## 字段

| 字段 | 含义及已确定约束 |
| --- | --- |
| flow_id | 流水主键，雪花 ID |
| flow_type | 资金效果类型 |
| amount | 该类型所表达的业务金额，整数分 |
| biz_id | 业务编号，由流水类型确定其所属业务 |
| created_at | 流水记录创建时间 |

## 约束与业务使用

约束：主键 flow_id；UNIQUE(flow_type, biz_id)。只记录已提交的资金效果，不增加“处理中／失败”的流水状态。

### 已确认的类型与金额语义

D 为押金，R 为尾款，P = D + R，S 为卖家所得，F 为平台收入。

| 类型 | amount | 可用变化 | 冻结变化 | biz_id 来源 |
| --- | --- | --- | --- | --- |
| 充值 | 充值金额 | 用户增加 | 0 | 稳定充值业务编号 |
| 押金冻结 | D | 用户 −D | +D | 报名 ID |
| 押金解冻 | D | 用户 +D | −D | 报名 ID |
| 购买付款 | P | 买家 −R | −D | 订单 ID |
| 成交结算 | S | 卖家 +S | 0 | 订单 ID |
| 押金扣除／违约扣款 | D | 买家 0 | −D | 订单 ID |
| 流拍补偿 | S | 卖家 +S | 0 | 订单 ID |
| 平台收入 | F | 不修改用户钱包 | 不修改用户钱包 | 订单 ID |

购买付款记录完整成交价，零尾款也有该流水。冻结不算消费，不能把所有流水正数 amount 相加作为营收。正常和超时的同订单平台收入使用同一业务唯一键，实际分支由订单状态互斥。

### 语义已确认、物理字段待定

必须能表达用户或平台记账主体、必要交易对手、可用余额变化及冻结金额变化；具体字段名、主体引用、可空约束尚未确认。原 from_account_id／to_account_id 均引用真实账户的模型不再适用于全部类型，不能假造平台账户 ID。

每种资金效果有独立 flow_id。一个结算事务三条流水不能共用主键；任务重发保持原流水身份，任务预分配多编号的存储方式见 fund_outbox。
